# GOST Sidecar Egress Control Demo

This demo runs `main` from a small Debian-based image and makes it share the
network namespace owned by `egress-control-sidecar`. The egress-control sidecar
is built from `gogost/gost` with `nftables` added. The sidecar image includes
its config under `/opt/egress-sidecar`, installs the `policy` command on
`PATH`, and starts GOST. By default it does not install the nft transparent
proxy rules, so egress is allow-all until `policy allow ...` or
`policy deny-all` is applied.

The `egress-control-sidecar` Dockerfile pins the GOST base image as
`gogost/gost:3.2.6@sha256:1ae76fcd556aec335ff602a1828c1140c27d6243c7f02a89f41e177baa265faf`.
The exact version tag documents the intended source release; the digest is what
fixes the actual image content.

The main Dockerfile pins Debian as
`debian:13.5-slim@sha256:b6e2a152f22a40ff69d92cb397223c906017e1391a73c952b588e51af8883bf8`
and installs `curl`, `dnsutils`, `iputils-ping`, and `ca-certificates` for the
checks in this README.

## Start

```bash
docker compose up --detach
```

`main` has no independent network namespace:

```yaml
network_mode: "service:egress-control-sidecar"
```

That means nft rules installed by `egress-control-sidecar` apply to traffic
generated by `main` after a controlled policy is enabled. `main` may run as root
or as a regular user.

The compose file shows these optional guardrails commented out:

```yaml
# cap_drop:
#   - ALL
# security_opt:
#   - no-new-privileges:true
```

These two lines are not required for the happy-path curl checks to work. The
demo will often still appear to work without them because Docker does not give a
normal container `CAP_NET_ADMIN` by default. Enable them for untrusted code:
`main` should not be able to set socket marks, create raw sockets, regain
capabilities through setuid/file-capability execution, or change the shared
network namespace.

Do not add `privileged: true`, `cap_add`, host networking, host PID namespace,
or a Docker socket mount to `main`. Those would change the threat model. In
particular, if code in `main` can set `SO_MARK=114514`, it can impersonate
GOST-marked traffic and bypass the transparent proxy.

## Policy Commands

Default state is allow-all: the demo-owned nft table is absent and the
transparent proxy is disabled.

```bash
docker compose exec egress-control-sidecar policy show
docker compose exec egress-control-sidecar policy allow-all
docker compose exec egress-control-sidecar policy deny-all
docker compose exec egress-control-sidecar policy allow api.gitlab.com
docker compose exec egress-control-sidecar policy allow '*.github.com' 8.8.8.8
docker compose exec egress-control-sidecar policy allow api.gitlab.com api.moonshot.ai '*.github.com' 8.8.8.8
docker compose exec egress-control-sidecar policy allow api.gitlab.com '*.github.com' 1.1.1.0/24
```

`policy allow-all` removes the demo-owned nft table and clears the allowlist.
That disables the transparent proxy and restores direct egress.

To allow the requested demo targets, run:

```bash
docker compose exec egress-control-sidecar policy allow api.gitlab.com api.moonshot.ai '*.github.com' 8.8.8.8
```

GOST reloads `/opt/egress-sidecar/allowlist.txt` every second, so policy changes
take effect without restarting the container.

The allowlist file is inside the `egress-control-sidecar` container filesystem,
not bind-mounted from the host. Recreating `egress-control-sidecar` from the
image resets it to the demo default.

`policy allow` replaces the whole allowlist and enables the transparent proxy.
`policy deny-all` clears the allowlist and also enables the transparent proxy,
so controlled TCP egress is denied. Targets can be:

```text
api.gitlab.com                 exact domain
*.github.com                   wildcard domain
.github.com                    domain suffix, including github.com itself
8.8.8.8                        exact IP
1.1.1.0/24                     CIDR
192.168.1.1-192.168.1.10       IP range
example.com:443                address with port
```

## Quick Checks

The following examples assume the stack is already running:

```bash
docker compose up --detach
```

Check the default mode. It should be allow-all and there should be no
demo-owned nft table:

```bash
docker compose exec egress-control-sidecar policy show
docker compose exec egress-control-sidecar policy rules
```

In allow-all mode, direct TCP and HTTP/3 work because the transparent proxy is
disabled:

```bash
docker compose exec main curl --head --max-time 5 https://example.com
docker compose exec main curl --http3-only --head --max-time 5 https://www.google.com
```

Enable controlled deny-all. TCP now goes through GOST, but the allowlist is
empty, so controlled TCP egress is denied:

```bash
docker compose exec egress-control-sidecar policy deny-all
docker compose exec main curl --head --max-time 5 https://api.gitlab.com
```

ICMP remains allowed in controlled mode, so basic diagnostics still work:

```bash
docker compose exec main ping -c 1 -W 2 8.8.8.8
```

UDP is rejected in controlled mode. That includes HTTP/3:

```bash
docker compose exec main curl --http3-only --head --max-time 5 https://www.google.com
```

Allow the requested demo targets. `policy allow` replaces the whole allowlist:

```bash
docker compose exec egress-control-sidecar policy allow api.gitlab.com api.moonshot.ai '*.github.com' 8.8.8.8
docker compose exec main curl --head --max-time 5 https://api.gitlab.com
docker compose exec main curl --head --max-time 5 https://api.github.com
```

GitHub may return `HTTP/2 403` when the unauthenticated API rate limit is
exhausted. That still shows the connection was allowed; a GOST deny failure
looks like a TLS EOF from `curl`.

Unlisted TCP targets are still denied while controlled mode is enabled:

```bash
docker compose exec main curl --head --max-time 5 https://example.com
```

Close controlled TCP egress again:

```bash
docker compose exec egress-control-sidecar policy deny-all
docker compose exec main curl --head --max-time 5 https://api.github.com
```

Docker embedded DNS remains available through loopback, but direct external
UDP DNS is rejected in controlled mode:

```bash
docker compose exec main dig api.gitlab.com +time=2 +tries=1
docker compose exec main dig .8.8.8 google.com +time=2 +tries=1
```

Return to direct allow-all egress:

```bash
docker compose exec egress-control-sidecar policy allow-all
docker compose exec main curl --head --max-time 5 https://api.github.com
docker compose exec main curl --http3-only --head --max-time 5 https://www.google.com
```

CIDR allowlist example over TCP:

```bash
docker compose exec egress-control-sidecar policy allow 1.1.1.0/24
docker compose exec main curl --head --max-time 5 https://1.1.1.1
```

## How It Works

When controlled mode is enabled, `policy` installs two nft `output` hooks in the
shared network namespace:

```text
main TCP egress -> nft NAT redirect :12345 -> GOST red:// listener
main UDP and other non-TCP egress -> nft filter reject
main ICMP egress -> nft filter accept
```

In controlled mode, UDP is intentionally closed. That includes QUIC and HTTP/3,
so clients must use TCP transports such as HTTPS over HTTP/1.1 or HTTP/2. ICMP
is allowed so basic diagnostics such as `ping` can still work.

GOST restores the original destination with `SO_ORIGINAL_DST`. This supports IP
and CIDR matching. With `sniffing: true`, it can also read HTTP Host or TLS SNI
and match domain rules such as `api.gitlab.com` and `*.github.com`.

The service metadata sets `so_mark: 114514`. GOST applies `SO_MARK=114514` to
its own outbound sockets, and nft returns marked packets immediately. This
prevents GOST's upstream connections from being redirected back into GOST.

The nft rules trust only packets marked with `SO_MARK=114514`, not a particular
UID. That lets `main` run as root or as a regular user. Dropping capabilities is
a defense against future or accidental bypass paths, not what makes the normal
TCP redirect work. The filter hook rejects non-loopback, non-TCP packets unless
they are GOST-marked or ICMP. That keeps Docker's embedded DNS on `127.0.0.11`
available, keeps TCP going through GOST, permits ICMP diagnostics, and prevents
code in `main` from bypassing GOST with UDP or direct network-namespace
changes.

`policy rules` prints only the demo-owned nft table when controlled mode is
enabled:

```bash
docker compose exec egress-control-sidecar policy rules
```

Docker may create its own container-networking rules through the `iptables-nft`
compatibility frontend, especially around `127.0.0.11`. Those rules are
Docker-managed and separate from this demo. This demo's egress policy is
implemented only with the native nft table `inet gost_egress`.

## Scope

This is intentionally a small TCP egress demo. Default startup is allow-all.
Controlled mode starts when `policy allow ...` or `policy deny-all` installs the
demo-owned nft table. In controlled mode, DNS to Docker's embedded resolver is
not blocked because it stays on loopback. TCP is controlled by GOST allowlist
rules; non-loopback UDP and other non-proxied traffic are rejected by nft, while
ICMP is allowed for diagnostics. QUIC and HTTP/3 are disabled by design. Domain
rules depend on HTTP Host or TLS SNI; non-HTTP/TLS traffic is controlled by
destination IP/CIDR.
